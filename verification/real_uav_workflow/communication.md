# 启动前后各 20 秒通信测试

由 [现场工作流](README.md#6-提醒用户选择通信测试) 调用。方法参考 [10-12 报告 §1、§8](../../quality_reports/2026-10-12_airlink_scaling_test.md)；复用已有 tx/rx 工具，不依赖历史 `/tmp/radio_sample.py`。

## 固定条件

| 项目 | A：启动前 | B：启动后 |
|---|---|---|
| 我方机载栈 / GCS 栈 | 全停 | 全开、稳定、已检查实际消息连通 |
| router | 保持服务与同一端点配置 | 不变 |
| UAV、摆位、网卡、电台设置 | 相同并记录 | 不变 |
| UDP 上行负载 | 每机 1 Mbps，1200 B，20 s | 同 A |
| ping RTT | GCS → 每机，0.5 s 间隔，20 s | 同 A |
| 计数器 | GCS 及每台 UAV 实际电台网卡 | 同 A |

此为**附加负载下**的 RTT 对照；5 机就是额外 5 Mbps，并非日常生产流量。扩到更多机时，不机械叠加 1 Mbps/机：先选定合理的每机或聚合负载并写入本轮记录，A/B 必须相同。不得拿压测 RTT 当作无附加负载的生产 RTT。需要区分时另做一对**不注入 UDP**的 20 s A/B，并独立标注，不能事后换口径。

负载测试仅限拆桨、disarm、非 OFFBOARD 的地面状态。测量时不 rsync/build/下载日志，不调整 router/packing，不新启或重启节点。非参与但在线的 UAV 也可能占空口，须记录背景节点；AI 不擅自关其它设备。

## 准备一次

- tx/rx 源码在 `verification/airlink_test/`；将本机 `airlink_tx.py` 用 rsync 同步到**每台**机载 `~/airlink_tx.py` 并校验文件。记录工具版本/校验和，与机载源码同步分开记。
- GCS 检查 UDP 5700 无旧接收器占用。逐机 `ip route get 192.168.5.241` 找到实际电台出口；GCS 用到机载 IP 的路由确定网卡，不假定一直是 `eth0/enp5s0`。
- 先建立 SSH 连接（可复用连接），准备并发调度。各机发送/探测窗口尽量同时，记录每项实际起止时间；不能串行每架测 20 s 再称为多机同时测试。
- 下文命令是组成部分，须由 AI 按上述并发顺序编排、重定向到本轮 A/B 子目录；**占位符不能直接执行**。每个后台任务须等待完成并核对退出码，不能把 SSH 启动成功当作测量完成。

## 每轮动作（A 和 B 各一次）

1. 建 `RUN_DIR/comm_A/` 或 `comm_B/`，记录起止时间、机队、状态、负载参数；先起 GCS 接收器，再确认监听成功：

   ```bash
   python3 -u verification/airlink_test/airlink_rx.py \
     --proto udp --port 5700 --size 1200 --duration 30
   ```

   接收器多出的时间只供建连与收尾；所有发送端仍各测 20 s。全部启动必须落在其监听窗口内，否则本轮无效，不能按截断数据报丢包。
2. 并发执行各机发送、GCS 逐机 ping、GCS/各机计数器采样：

   ```bash
   # 每台机载，通过 SSH 运行；所有机并发
   python3 -u ~/airlink_tx.py --proto udp --host 192.168.5.241 \
     --port 5700 --rate 1M --size 1200 --duration 20
   # GCS，每个目标各一个进程，并发
   LC_ALL=C ping -n -D -i 0.5 -w 20 <机载IP>
   # GCS 与每台 UAV：在本地各运行一份，起止采样对应这轮窗口
   date -Ins
   cat /proc/net/dev /proc/net/snmp
   sleep 20
   date -Ins
   cat /proc/net/dev /proc/net/snmp
   ```

   ping 窗口须与 UDP 负载窗对齐；若 SSH 启动错位明显，保留原始结果并标注“混合空载/有载”，修正调度后重测，不能作为严格有载对照。实际测量时长写入记录，不因 SSH/收尾耗时把测试延长成数分钟。
3. 等 tx/rx/ping 全结束，核对目标数、每机 tx `[done]`、接收来源 IP、完整覆盖窗口；ping 无回复也要保留并写 FAIL。部分发送器未运行时，该机写“发送失败/无效”，不写 0% 丢包。
4. B 额外保留：当前会话的 bridge `health_start`、测量窗前后 health 样本、各邻机 `swarm_pose` 收发情况与 stall/link/协议错误。原始文件在各机 `~/catkin_swarm6-2/.ros_home/log/health/`；压力流量停止后再下载。可读采样在测试期间落机载本地文件，避免持续 SSH 拉流增加干扰。

## 统计口径

- **延迟主指标**：ping RTT min/avg/max/mdev（ms）与 ICMP 丢包率。它不依赖板钟，但 ICMP 往返与 ROS 应用消息延迟不是同一指标。工具输出的 owdelay 不用于绝对值，也不把 RTT/2 当成实测单向延迟。
- **UDP**：从每个 tx 最终包数和对应 rx 收到包数核对损失；rx 的 seq 区间丢包率漏计首尾全丢，不能只照抄。全窗完整时可用 `(tx包数-rx包数)/tx包数`；有重复/乱序等异常先核查（现工具不去重），不报负丢包率。来源缺失但 tx 证实发送完整时写 100% 丢包。
- **包率/吞吐**：实际电台网卡 `ΔRX_packets/Δt`、`ΔTX_packets/Δt`；Mbps 用 `8×Δbytes/Δt/10^6`。记录每台 UAV，不能只读 GCS——机间流量不经过 GCS。接口统计含探测、MAVLink、TCP ACK 等背景流量；不冒称“纯 bridge 包率”或全网空口 pps。
- **TCP 重传**：同窗 `/proc/net/snmp` 的 `Tcp RetransSegs/OutSegs` 增量，标为整机统计。bridge health 的帧/消息计数不是实际网卡包数，不可直接等同。
- **机间消息连续性**：比较窗前后各源 rx/tx、`gt1000`、`stalls` 增量及窗内事件。历史累计 gap 最大值不等于本轮新断口；限频丢弃/`latest` 替换中间样本不等同网络丢包。板钟仅粗对齐时，跨机窗口筛选有边界误差，须同时保存各机本地起止采样。

|---|---|---|---|---|---|---|
| UAVn | 待测 | 待测 | 待测 | 待测 | B−A | 待测 |

先判断本轮是否有效，再判断是否存在延迟回归。**没有项目已验收的统一 RTT 上限，不凭历史 60–90 ms 或预测 pps 自动盖 PASS。** 若本轮另有现场确认的阈值，测试前写入记录，不能看结果后改线。

发现 500 ms 级排队重现、异常丢包、≥1 s 机间断口或协议失配，标异常并停止飞行交接，保留证据定位；高 UDP 压力导致异常时，可停止压力流量补测生产流量，但须分别报告，不能覆盖原失败结果。无异常写“20 s 地面快测未发现异常，实飞未验证”。本流程 A/B 同时改变运行栈状态，只检验新版本启动带来的负载影响，**不能单独证明合包相对 legacy 的改进幅度**。

不自动进行 legacy 回滚或修改合包频率；需要专门对比时另建地面实验，确保全队及 GCS 一致切换并保留原配置。20 s 快测也不证明 30+ 机容量或长时稳定性。
